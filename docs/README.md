# 設計ドキュメント

| 文書 | 内容 | 読むとき |
|---|---|---|
| [design.md](design.md) | いまの設計: 構成、処理の流れ、IME と入力位置の取得、負荷対策、表示と見た目、設定 | コードを変える前に必ず |
| [decisions.md](decisions.md) | 判断とその理由、採用しなかった案 | 設計を変えたくなったとき(同じ案を試し直さないため) |
| [app-compatibility.md](app-compatibility.md) | アプリの種類ごとの取得方法と、アプリ別の検証結果・癖 | 入力位置や IME 判定の不具合を調べるとき |
| [development.md](development.md) | ビルド、ツール、出力ファイルの置き場と名前、確認手順、リリース手順 | 作業を始めるときと、リリースするとき |
| [roadmap.md](roadmap.md) | 制限事項、未確認のこと、今後の候補 | 次に何をするか決めるとき |

## 書き方の決まり

- いまの状態を書く。経緯は「何を試して、なぜやめたか」だけを [decisions.md](decisions.md) に残し、日付・作業の回数・作業者は書かない。
- 個人の環境に依存する情報(ユーザー名を含むパス、個人が使っているアプリの名前、画面の内容)は書かない。アプリ名は Windows 標準や広く使われているものだけにする。
- 数値は、測った条件(DPI、コア数など)と一緒に書く。測り直したら書き換える。
- 利用者から見える変更は、ルートの [CHANGELOG.md](../CHANGELOG.md) にも書く。
