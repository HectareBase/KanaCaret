# 設計

KanaCaret は、テキストキャレット(文字入力位置)の少し上に、IME が日本語入力なら「あ」、直接入力なら「a」を表示する常駐アプリ。

## 目標

| 項目 | 目標 | 現状(16 論理コア、120 DPI で計測) |
|---|---|---|
| 何もしていないときの CPU | 1 コアあたり 0.1% 前後 | 0.10% |
| 入力中の CPU | 小さく抑える | メモ帳で毎秒 8 文字入力して 0.6〜1.1% |
| メモリ | 小さく抑える | プライベート 5.7〜6.5MB(Direct2D/DirectWrite で約 3〜4MB) |
| 実行ファイル | 単一 exe、ランタイム不要 | 約 290KB(アイコン・設定画面込み、CRT 静的リンク) |
| IME 切り替えの反映 | 150ms 以内 | 入力直後は 100ms ごとに確認 |
| 対応 OS | Windows 11 | Windows 10 は未確認 |

計測は `tools\measure-load.ps1` で行う([development.md](development.md))。

## 構成

```
src/
  main.cpp            制御の中心。Update()(状態の確認と表示)、WinEvent フック、タイマー、
                      通知領域のメニュー、設定の反映、--stats の記録
  ImeMonitor.*        IME 状態の問い合わせ(WM_IME_CONTROL)
  CaretLocator.*      フォーカスのあるウィンドウの特定と、Win32/MSAA での入力位置の取得、矩形の妥当性チェック
  UiaWorker.*         UI Automation で入力位置を問い合わせる専用スレッド
  IndicatorWindow.*   表示用の層状ウィンドウ(配置、フェード)
  Renderer.*          Direct2D/DirectWrite でバッジを描く(インジケーター、設定画面の見本とプレビュー、exe のアイコン)
  Theme.*             Windows の配色設定の読み取りと、バッジの配色
  Settings.*          settings.ini と自動起動(Run キー)
  SettingsWindow.*    設定画面(開いている間だけ作る)
  AppList.*           ウィンドウのあるアプリの一覧(設定画面の「アプリ」に使う)
  DarkMode.*          設定画面とメニューのダーク表示(公開されていない uxtheme の関数を序数で呼ぶ)
  TrayIcon.*          通知領域のアイコンとメニューの表示
resources/
  app.manifest        PerMonitorV2 DPI 対応、Common Controls v6
  app.rc, app.ico     アイコンとバージョン情報(バージョン番号は version.h.in 経由で CMakeLists.txt から入る)
probe/                検証ツール ime-probe(アプリごとに取得方法を調べる)
installer/            インストーラーの NSIS スクリプト(tools/package.ps1 から作る)
tools/                確認・計測・配布のツール(development.md)
```

スレッドは UI スレッドと UIA 用ワーカースレッドの 2 本。UIA の呼び出しは別プロセスとの通信で最大 1 秒止まることがあるため、ワーカーで行い、結果を `PostMessage` で UI スレッドに返す。

## 処理の流れ

すべての処理は `main.cpp` の `Update(reason)` に集まる。呼ばれるきっかけは次の 5 つ。

| きっかけ | reason | 内容 |
|---|---|---|
| `EVENT_SYSTEM_FOREGROUND` / `EVENT_OBJECT_FOCUS`(システム全体) | Focus | 手前のアプリやフォーカスが変わった |
| `EVENT_SYSTEM_MOVESIZESTART/END`(システム全体) | Caret | ウィンドウの移動・サイズ変更が始まった・終わった |
| `EVENT_OBJECT_SHOW/HIDE/LOCATIONCHANGE`(`OBJID_CARET` のみ、フォーカス中のアプリだけ) | Caret | キャレットが出た・消えた・動いた。33ms 以内に続いたものは 1 回にまとめる |
| 100ms のタイマー | Tick | IME の切り替えの確認と、通知の来ないアプリの追従 |
| UIA ワーカーの結果 | UiaResult | 結果を反映して表示だけ更新する |

`Update()` の手順:

1. フォーカスのあるウィンドウを調べる(`GetGUIThreadInfo`。UWP は子の `CoreWindow` を見る)。自分自身なら隠す。
2. フォーカスが変わったら、取得方法の記録をリセットし、そのアプリが表示の対象かを調べ、キャレット用のフックをそのアプリに付け替える(付け替えはメッセージループに戻ってから。対象外のアプリには付けない)。
3. 対象外のアプリなら隠す。IME も入力位置も問い合わせない。
4. ウィンドウの移動・サイズ変更中(手前のアプリの `GUITHREADINFO` に `GUI_INMOVESIZE`)なら、覚えていた入力位置を捨てて隠す。終わった最初の `Update()` では、すぐ入力位置を問い合わせ直す。
5. フルスクリーン中(1 秒に 1 回 `SHQueryUserNotificationState`)なら隠す。
6. 必要なときだけ IME の状態を問い合わせる(下の「負荷を抑える仕組み」)。取得できなければ隠す。
7. 表示モードで隠す状態、または「入力中は隠す」で入力中なら、入力位置は問い合わせずに隠す(下の「入力中は隠す」)。
8. 入力位置を取得する(下の「入力位置の取得」)。
9. 取れたらキャレットの位置に表示し、取れなければ隠す。

## IME 状態の判定

1. `ImmGetDefaultIMEWnd(フォーカスのあるウィンドウ)` で IME ウィンドウを得る。
2. `SendMessageTimeout(WM_IME_CONTROL, IMC_GETOPENSTATUS)` で ON/OFF を得る。OFF なら「a」。
3. ON なら `IMC_GETCONVERSIONMODE` を得て、`IME_CMODE_NATIVE` が立っていれば「あ」、なければ「a」(IME オンの半角英数モード)。
4. 応答が無い・権限が足りない(管理者権限のアプリ)ときは「不明」として隠す。

IME をオフにしても変換モードの NATIVE ビットは立ったままなので、ON/OFF を先に見るのが必須。プロセス外から読めるのはこの方法だけ([decisions.md](decisions.md))。

## 入力位置の取得

| 順 | 方法 | 主な対象 | 実装 |
|---|---|---|---|
| 1 | Win32 のシステムキャレット(`GetGUIThreadInfo` の `rcCaret`) | メモ帳など Win32 アプリ | `CaretLocator.cpp` |
| 2 | MSAA(`AccessibleObjectFromWindow(OBJID_CARET)`) | Chromium / Electron | `CaretLocator.cpp` |
| 3 | UI Automation(`TextPattern2::GetCaretRange` → 範囲の矩形 → 直後の 1 文字の左端 → 直前の 1 文字の右端) | WinUI/UWP(エクスプローラーの検索欄、設定アプリ、スタートメニュー)、Windows Terminal | `UiaWorker.cpp`(非同期) |

取得した矩形は、次の条件をすべて満たすときだけ使う(`PlausibleCaret`)。

- 高さが 6〜120 DIP、幅が高さ以下(文書全体や選択範囲、高さ 1px の矩形をはじく)
- 画面内にある(アニメーション中の画面外の座標をはじく)
- MSAA で幅 0 でない(Chromium が前の入力欄の古い位置を幅 0 で返す)

取得方法の使い分け:

- **Chromium/Electron(クラス名が `Chrome_` で始まる)では UIA を使わない。** UIA は古い位置のまま更新されないことがある。
- **Win32 で取れたウィンドウでは、以後 Win32 だけを試す**(MSAA のプロセス間通信を減らす)。メモ帳はしばらく操作しないとキャレットを破棄するので、フォーカスが移るまで最後の位置に表示し続ける。
- **UIA でしか取れなかった入力欄は「exe 名|ウィンドウクラス」で覚え**、次からは Win32/MSAA を飛ばして UIA へ進む。ただし UIA で問い合わせる前に毎回 Win32 を確かめ、取れたら Win32 に戻す(開いた直後のメモ帳はキャレットが無く、UIA で取れてしまうため)。
- UIA の問い合わせは 1 件ずつ。前の問い合わせが終わっていなければ、その回は飛ばす。タイムアウトは 1 秒。
- キャレットが一瞬消えても(再描画のたびに `HideCaret` するアプリ)、300ms は最後の位置に表示し続ける。

アプリ別の結果と癖は [app-compatibility.md](app-compatibility.md)。

## 負荷を抑える仕組み

`main.cpp` の定数で調整する。`--stats` の記録で効果を確かめられる。

| 仕組み | 定数 | 理由 |
|---|---|---|
| キャレット用のフックはフォーカス中のアプリだけに付ける | — | システム全体だと、無関係なウィンドウの移動・表示の通知が毎秒 100 件以上届く |
| キャレットの通知を 33ms ごとにまとめる | `kCaretCoalesceMs` | Chromium は 1 回のキー入力で何度も通知する |
| キャレットの通知では IME を問い合わせない | — | IME の切り替えは 100ms ごとの確認で拾える |
| 入力から 0.5 秒以内だけ 100ms ごとに IME を確認し、それ以外は 1 秒ごと | `kImeActiveMs`, `kImeIdlePollMs` | IME の切り替えはほぼキー操作で起きる(`GetLastInputInfo` で判定) |
| UIA は入力から 2 秒以内だけ 250ms ごと、それ以外は 2 秒ごと | `kUiaActiveMs`, `kUiaPollMs`, `kUiaIdlePollMs` | UIA は 1 回で約 3ms の CPU を使う |
| 通知が来るアプリでも取りこぼし対策で問い合わせ直す: 入力中 1 秒、それ以外 5 秒 | `kRelocateMs`, `kIdleRelocateMs` | |
| 対象外のアプリでは IME も入力位置も問い合わせず、キャレットの通知も受けない | — | |
| 表示モードで隠している間は入力位置を問い合わせない | — | 「切り替えたときだけ表示」が最も軽い |
| 画像は状態・テーマ・DPI・大きさが変わったときだけ描き直す。移動は位置だけ変える | — | |

タイマー自体は常に 100ms で動かす。入力が無い間は何も問い合わせないので、起きても負荷はほとんど無い。

## 入力中は隠す

設定(`HideWhileTyping`)をオンにすると、キー入力から 1 秒(`kTypingHideMs`)は隠し、手を止めると表示し直す。入力中の文字で日本語か英語か分かるため。どの表示モードとも組み合わせられる。

- キー入力の判定: `Update()` のたびに `GetLastInputInfo` の時刻とマウスカーソルの位置(`GetCursorPos`)を見て、時刻が進んだのにカーソルが動いていなければキー入力とみなす(`TrackTyping`)。キーボードのフックは使わない([decisions.md](decisions.md))。その場でのクリックやホイールもキー入力に数えてしまうが、隠れるのは 1 秒だけ。
- IME を切り替えたときと、フォーカスが移ったときは、その時刻(`revealAt`)から 300ms(`kRevealGraceMs`)より後のキー入力があるまで表示する。`GetLastInputInfo` はキーやマウスボタンを離したときにも進むので、猶予が無いと、入力欄をクリックした直後や切り替えのキーを離した直後に 1 秒隠れてしまう(入力欄を移るたびに、表示が遅れて見えた)。
- 隠している間は入力位置を問い合わせないので、負荷は増えない。

## 表示

- ウィンドウ: `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`。クリックを透過し、フォーカスを奪わず、タスクバーや Alt+Tab に出ない。フォーカスが変わるたびに最前面を付け直す。
- 描画: `UpdateLayeredWindow` に 32bpp のプリマルチプライド DIB を渡す。フェードは全体の不透明度だけを変える(フェードイン 83ms、フェードアウト 167ms、ease-out。「アニメーション効果」がオフなら即時)。フェードインの行き先は設定の不透明度(30〜100%)。
- 大きさ: 14〜40 DIP の正方形(既定 22)。影のために周囲に 6 DIP の余白を持つ。
- 配置(キャレットとの間は設定の 0〜16 DIP、既定 4):
  - 上: 左端をキャレットにそろえ、キャレットの上
  - 右上: キャレットの右で、下端をキャレットの上端にそろえる
  - 下: キャレットの下
  - 作業領域からはみ出すときは上下を入れ替える。
- DPI: すべて物理ピクセルで扱い(PerMonitorV2)、キャレットのあるモニターの DPI で大きさを決める。

## 見た目

| 状態 | 背景 | 枠 | 文字 |
|---|---|---|---|
| 「a」ライト | `#F9F9F9` | `#8A8A8A` | `#1B1B1B` |
| 「a」ダーク | `#3A3A3A` | `#9A9A9A` | `#FFFFFF` |
| 「あ」ライト | アクセント Dark1 | 同左 | 白 |
| 「あ」ダーク | アクセント Light2 | 同左 | 黒 |
| ハイコントラスト | `COLOR_WINDOW` / 「あ」は `COLOR_HIGHLIGHT` | `COLOR_WINDOWTEXT` | `COLOR_WINDOWTEXT` / `COLOR_HIGHLIGHTTEXT` |

- 「a」の濃い枠は、暗いアプリの上でも輪郭が見えるようにするため(Fluent の ControlStrongStroke 相当)。
- 「あ」の塗りは Fluent の AccentFillColorDefault に合わせる。アクセントは `HKCU\...\Explorer\Accent\AccentPalette` から読む。設定で「グレー」を選ぶと「a」と同じ配色になる。
- 設定画面で色を選んだとき(`FillChoice::Custom`)は、選んだ色をライトでもダークでもそのまま塗る。文字は背景との差が大きいほう(相対輝度 0.18 を境に白か黒)、枠は背景を文字色へ 25% 寄せた色にする。読めない組み合わせを作れないよう、背景色だけを選んでもらう。ハイコントラストのときは選んだ色を使わない。
- 角の丸みは箱の 5/22、文字は箱の 13/22。「あ」は Yu Gothic UI、「a」は Segoe UI Variable Text(無ければ Segoe UI)、どちらも Semibold。背景が透明なので文字はグレースケールのアンチエイリアス。
- 影: 角丸を少しずつ大きくして薄く重ねる(6 層、広がり 4 DIP、下へ 1 DIP。不透明度はライト 16%、ダーク 30%)。設定の「影の濃さ」(0〜200%)をこの不透明度に掛ける。
- テーマの変更は `WM_SETTINGCHANGE` / `WM_SYSCOLORCHANGE` / `WM_DWMCOLORIZATIONCOLORCHANGED` で読み直す。インジケーターと設定画面はアプリのテーマ(`AppsUseLightTheme`)に合わせる。
- 通知領域のアイコンは exe のアイコン(`LoadIconMetric` で小さいアイコンの大きさに合わせて読む)で、IME の状態では変えない。exe のアイコンは `badge-preview.exe --ico` で作る(既定のアクセント `#005FB8` の「あ」)。

## 設定と常駐

設定は `%APPDATA%\KanaCaret\settings.ini`(UTF-16、セクション `[Indicator]`)。設定画面や通知領域のメニューで変えるとすぐ保存する。

| キー | 値 | 既定 |
|---|---|---|
| `Mode` | 0 = 入力欄にいる間は常に表示、1 = 切り替えたときだけ(1.5 秒)、2 = 日本語入力のときだけ | 0 |
| `HideWhileTyping` | 1 = キー入力の間は隠す | 0 |
| `Placement` | 0 = 上、1 = 右上、2 = 下 | 0 |
| `SizeDip` | バッジの大きさ(14〜40 DIP) | 22 |
| `KanaColor` | 「あ」の塗り: `auto` = アクセントカラー、`neutral` = 「a」と同じ、`#RRGGBB` | `auto` |
| `LatinColor` | 「a」の塗り: `auto` = テーマに合わせる、`#RRGGBB` | `auto` |
| `Opacity` | 不透明度(30〜100%) | 100 |
| `GapDip` | キャレットとの間隔(0〜16 DIP) | 4 |
| `Shadow` | 影の濃さ(既定の濃さに対する 0〜200%) | 100 |
| `AllApps` | 1 = すべてのアプリで表示、0 = `Apps` に挙げたアプリだけで表示 | 1 |
| `Apps` | 表示するアプリの exe 名(小文字、カンマ区切り)。`AllApps=1` の間も消さずに残す | 空 |

- 以前の `Size`(0/1/2 → 18/22/28)と `AccentKana`(1 → `auto`、0 → `neutral`)は、新しいキーが無いときだけ読み替える。廃止した `MouseFallback` と `Exclude`(除外するアプリ)は読まない。保存するときに、これらの以前のキーは消す。
- 自動起動は `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` の値 `KanaCaret`(exe のパス)。ini には持たない。
- 二重起動は名前付き Mutex `Local\HectareBase.KanaCaret.SingleInstance` で防ぐ。
- インストーラー(`installer/KanaCaret.nsi`)は、メインウィンドウのクラス名と Run の値の名前に頼っている(起動中のアプリへの `WM_CLOSE` と、アンインストール時の自動起動の削除)。これらの名前を変えるときは、インストーラーも合わせる。
- 他のアプリと重ならないよう、PC 内で共有される名前には持ち主名を含める: Mutex、ウィンドウクラス(`HectareBase.KanaCaret.Main` / `.Indicator`)。設定フォルダーと Run の値は読みやすさを優先して `KanaCaret`。
- Explorer が再起動したら(`TaskbarCreated`)通知領域のアイコンを登録し直す。

## 設定画面と通知領域のメニュー

- 通知領域のアイコンをクリック(または Enter キー)すると設定画面を開き、右クリックでメニューを開く。`KanaCaret.exe --settings` でも開ける(起動中なら、そのプロセスに `WM_APP + 4` を送って開かせる)。
- メニューは「設定...」(既定の項目)、「一時停止」、「終了」だけ。表示するアプリは設定画面の「アプリ」で選ぶ。メニューもアプリのテーマに合わせてダークになる(`DarkMode`)。
- 設定画面(`SettingsWindow`)は、開いている間だけウィンドウを作り、閉じたら破棄する。常駐中の負荷とメモリは変わらない。
- 左にカテゴリ(表示 / 見た目 / アプリ / 全般)、右にそのページを出す。「見た目」には位置、大きさ、不透明度、キャレットとの間隔、影の濃さ、「あ」「a」の色、プレビューを置く。部品は標準のコントロール(コンボボックス、スライダー、チェックボックス、リストボックス、リストビュー)で、コードで作って DIP で配置する。`WM_DPICHANGED` で配置とフォントを作り直す。Tab キーでの移動はメッセージループで `IsDialogMessage` を呼んで行う。
- 色の見本とプレビューは `Renderer::DrawBadge` で描き、実際のバッジと同じ絵にする。プレビューはライトとダークの背景に、キャレットとバッジを、設定の位置・間隔・不透明度・影で並べる。
- 変更はすぐ保存して反映する(OK / キャンセルは置かない)。設定画面にフォーカスがある間、インジケーターは隠れる(手順 1)。
- 見た目はアプリのテーマに合わせ、テーマが変わるとすぐ切り替える。タイトルバーは Mica(`DWMSBT_MAINWINDOW`)で、ダークのときは `DWMWA_USE_IMMERSIVE_DARK_MODE` を付ける。
  - 標準のコントロールは、テーマ名で切り替える: ボタン・リストボックス・リストビュー・ツールチップは `DarkMode_Explorer`、コンボボックス・エディットは `DarkMode_CFD`。背景と文字の色は `WM_CTLCOLOR*` で返す。
  - そのために `SetPreferredAppMode`(序数 135)、`AllowDarkModeForWindow`(133)、`RefreshImmersiveColorPolicyState`(104)、`FlushMenuThemes`(136)を使う。序数の意味はビルドで違うので、ビルド 18362 以上で 4 つとも見つかったときだけ使い、それ以外はライトのまま表示する。
  - チェックボックスとスライダーは、標準の部品のまま NM_CUSTOMDRAW で自前で描く(標準のダーク表示が無いため)。
  - コンボボックスも標準の部品のまま自前で描く。一覧の行は `CBS_OWNERDRAWFIXED` の WM_DRAWITEM で(選んでいる行は左のカテゴリと同じく薄く塗ってアクセントの縦線)、閉じた欄はサブクラス(`SetWindowSubclass`)の WM_PAINT で角丸の欄と山形の矢印を描く。標準のままだと、ダークのテーマで一覧の選んでいる行が白地に白い文字になって読めない。ライトでもダークでも Windows 11 の形(角丸の箱、丸いつまみ)にそろえる。角丸や円は Direct2D(DC レンダーターゲット、ソフトウェア描画)で描く。
  - ハイコントラストのときはシステムの色を使い、ダークにしない。「その他の色...」の色の選択ダイアログは Windows 標準のもので、ライトのまま。

## 対象のアプリ(設定画面の「アプリ」)

- 「表示するアプリ」で「すべてのアプリ」(既定)か「チェックしたアプリだけ」を選ぶ。その下の一覧(チェックボックス付きのリストビュー)に、いまウィンドウを開いているアプリが並び、チェックを付けたものが `Apps` になる。
- 「すべてのアプリ」のときにチェックを付けると、「チェックしたアプリだけ」に切り替える。対象にしたいアプリを開いて、設定画面でチェックを付けるだけで済む。
- 一覧は、設定画面を開いたとき、設定画面が手前に戻ったとき(`WM_ACTIVATE`)、「一覧を更新」を押したときに作り直す。見ていた位置と選んでいた行は保つ。
- 一覧の作り方(`AppList.cpp`): Alt+Tab に出るウィンドウ(見えている、所有者が無い、ツールウィンドウでない、DWM で隠されていない、タイトルがある)を持つプロセスを集め、同じ exe は 1 つにまとめる。UWP は `ApplicationFrameWindow` の子の `CoreWindow` のプロセスを使う(フォーカスの判定と同じ)。自分自身と、exe のパスが読めないアプリ(管理者権限のアプリなど。どのみち IME の状態を読めない)は出さない。
- 表示名は、パッケージのアプリならスタートメニューと同じ名前(`GetApplicationUserModelId` → AppsFolder のシェル項目)、それ以外は exe のバージョン情報の FileDescription。行の右端に exe 名を薄い色で添える(表示名と同じなら添えない)。列を 2 つに分けると、ダークのテーマで列の境目に縦線が出るので、列は 1 つにして exe 名は `CDDS_ITEMPOSTPAINT` で描く。
- 対象に挙げてあるが今はウィンドウの無いアプリも、外せるように一覧の後ろに「(実行していません)」を付けて並べる。
- 設定を変えたら、フォーカスのあるアプリが対象かを、設定画面から戻ったときに調べ直す。

## 表示しない条件

- 入力位置が取れない(テキスト入力欄にフォーカスが無い、または入力位置を公開していないアプリ)
- IME の状態が取れない(管理者権限のアプリなど)
- ウィンドウの移動中・サイズ変更中
- 対象外のアプリ、フルスクリーンのアプリ・ゲーム・プレゼンテーション中、一時停止中
- 表示モードの条件に合わない
- 「入力中は隠す」がオンで、キー入力から 1 秒以内
